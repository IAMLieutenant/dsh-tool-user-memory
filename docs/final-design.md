# 最终设计：只记用户

2026-10-22，0.4.2。本页优先于旧版配置参考。

## 解决什么问题

用户开新对话后，仍希望使用少量长期个人偏好。收益来自少重复交代；代价来自错误记忆和维护。因此只保存明确的个人信息：手动确认，或在固定类别和当前用户原话核验后自动记录。

项目技术栈、任务进度、会话摘要不属于用户记忆。正常运行不读取或建立项目记忆，也不维护每个会话的长期记忆。

## 页面

只有“记忆、待确认、备份与迁移”三个入口和一个启用开关。没有项目选择、共享设置、索引选项、置顶设置、容量看板或诊断页。

记忆为空显示“暂无记忆。”，待确认为空显示“暂无待确认记忆。”。不在页面展示工具名或实现说明。

新增与普通编辑直接保存；助手建议仍需用户确认。新候选一次保存，替换同名旧内容时才展示新旧对照，修改后重新核对。

备份与迁移的原有界面及操作逻辑保持不变。

## 正常运行

- 默认启用，自动携带少量已确认用户偏好；关闭后停止后续注入和模型读取。
- 只提供用户记忆读取、搜索、提出候选、查看状态及受限自动记录五个工具，无项目主题工具或模型直接改写。
- 模型仅在用户明确要求保存长期个人偏好时提出候选，不能自动把聊天内容写成活动记忆。
- 正常流程不接入请求留档，不触发自动整理，不调用额外整理模型。
- 当前请求优先于旧记忆；记忆不构成执行操作的授权。
- 长度限制由程序处理，不把预算和索引变成日常设置。

旧接口的回归覆盖与正常运行分开。显式兼容入口保留历史存储能力，不作为当前产品流程。

## 数据

仍使用原有用户画像 Markdown；已保存的用户内容保持原样。旧项目文件和项目候选不合并进用户记忆，不参与正常读取或注入；备份迁移继续保留它们。

开关保存为画像旁的 version 2 policy JSON，只包含 enabled。旧版暂停、关闭或仅项目设置不会悄悄变成启用全局用户记忆；用户可在新页面明确开启。损坏设置保持停用，数据不删除。

删除与停用只影响后续提供。已进入对话的内容、历史快照、旧请求记录和备份仍可能保留，不把删除活动条目描述成彻底抹除。

消息选取使用有限的最近文本窗口；用户主动选择后才持久化引用。不扫描全部聊天、不读取推理。用户原话和助手回复来源区分保存。

## 验收

1. 页面一眼可见用户记忆，没有项目、会话、便签等额外概念。
2. 保存后新对话请求包含个人偏好，不包含旧项目索引。
3. 停用后不再读取或携带；删除后重新启用仍不携带被删内容。
4. 候选未确认不生效；替换旧内容需要核对，过期确认不能覆盖新修改。
5. 空状态只有一行；备份迁移保持原状并可操作。

测试只能证明流程与边界；实际模型是否正确遵循偏好、用户是否少重复交代，仍需真实使用判断。若自定义指令已足够，无需增加功能来证明插件有用。

自动记录限定职业背景、技能熟悉度、语言与表达偏好；程序核对当前用户原文并保守排除项目、流程规定、临时请求和转述。自然语言识别无法保证零误记，不明确就跳过。回答下方显示已记住并可撤销；撤销核对原记录，拒绝覆盖后续修改。没有额外模型或后台任务。
